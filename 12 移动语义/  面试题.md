1. 什么是移动语义？

标准回答：

移动语义是 C++11 引入的一种资源转移机制。它允许对象把内部资源的所有权转移给另一个对象，而不是重新分配并复制资源。对于管理堆内存、文件句柄、socket、智能指针等资源的对象，移动语义可以避免昂贵拷贝，并表达唯一所有权的转移。

2. std::move 的作用是什么？

标准回答：

std::move 本身并不移动资源，它只是把一个表达式强制转换成右值引用，使其可以匹配移动构造函数或移动赋值函数。真正发生资源转移的是类型自己的移动构造或移动赋值逻辑。

3. 移动构造函数一般怎么写？

标准回答：

移动构造函数接收一个右值引用参数，通常直接接管源对象的资源指针或句柄，然后把源对象置为空状态，避免源对象析构时释放已经转移的资源。移动构造通常声明为 noexcept。

示例：

Buffer(Buffer&& other) noexcept
    : data(other.data), size(other.size) {
    other.data = nullptr;
    other.size = 0;
}
4. 移动赋值函数一般怎么写？

标准回答：

移动赋值用于已经存在的对象，所以要先判断自赋值，再释放当前对象原有资源，然后接管源对象资源，最后将源对象置为空状态。最后返回 *this。

示例：

Buffer& operator=(Buffer&& other) noexcept {
    if (this != &other) {
        delete[] data;

        data = other.data;
        size = other.size;

        other.data = nullptr;
        other.size = 0;
    }

    return *this;
}
5. 移动构造和移动赋值有什么区别？

标准回答：

移动构造是在新对象创建时从另一个对象接管资源，新对象还没有旧资源；移动赋值是对一个已经存在的对象重新赋值，当前对象可能已经持有资源，所以必须先释放旧资源再接管新资源。

6. 什么是 Rule of Five？

标准回答：

如果一个类需要自定义资源管理，那么通常需要考虑五个特殊成员函数：析构函数、拷贝构造函数、拷贝赋值函数、移动构造函数、移动赋值函数。因为资源的释放、复制、移动都必须保持一致，否则容易出现内存泄漏、重复释放或悬空指针。

7. 什么是 Rule of Zero？

标准回答：

Rule of Zero 指的是尽量不要手写析构、拷贝、移动函数，而是使用标准库资源管理类，如 std::vector、std::string、std::unique_ptr 等，让它们自动管理资源。实际开发中优先 Rule of Zero，面试和底层封装中需要理解 Rule of Five。

8. 为什么移动构造函数通常要加 noexcept？

标准回答：

因为标准库容器在扩容或重新分配元素时，会根据移动构造是否可能抛异常来选择移动还是拷贝。如果移动构造不是 noexcept，std::vector 为了保证异常安全，可能会退回使用拷贝构造。给移动构造加 noexcept 可以让容器放心移动对象，提高性能。

9. 移动后的对象还能使用吗？

标准回答：

可以。移动后的对象仍然处于有效状态，可以析构、重新赋值，也可以调用满足其状态要求的成员函数。但它的具体值是未指定的，不能依赖它仍然保存原来的内容。

10. 右值引用变量本身是左值还是右值？

标准回答：

右值引用变量本身是左值。因为它有名字，可以取地址。因此在移动构造函数内部，如果要移动成员变量，需要显式写 std::move(other.member)。

11. unique_ptr 为什么不能拷贝但可以移动？

标准回答：

因为 unique_ptr 表示独占所有权，如果允许拷贝，就会出现两个 unique_ptr 管理同一块内存，导致重复释放。移动则是把所有权从一个 unique_ptr 转移给另一个，源指针变为空，不会产生重复释放问题。

12. 返回局部对象时为什么通常不写 std::move？

标准回答：

因为编译器可以进行返回值优化，比如 RVO 或 NRVO，直接在目标位置构造对象。显式写 return std::move(obj) 可能阻止某些优化。通常直接 return obj 更好。
