# 📝 CMake 多目录工程构建笔记

## 🎯 核心思维：基于目标（Target-Based）构建

在现代 CMake 中，核心原则是围绕目标（Target）配置依赖。

- **目标（Target）**：可以是编译出的可执行文件（Executable）或库文件（Library）。
- **传递性（Transitivity）**：通过给目标绑定属性（如头文件路径），CMake 会自动将这些配置传递给依赖该目标的其他模块。

---

## 📁 1. 标准项目目录架构

一个模块化、清晰的 C++ 工程目录结构通常如下：

```text
my_project/
├── CMakeLists.txt        # 🏠 根目录主配置文件（全局控制）
├── include/              # 📑 公共头文件目录
│   └── math_utils.h
├── src/                  # ⚙️ 核心逻辑/库代码目录
│   ├── CMakeLists.txt    # 🛠️ src 子目录配置文件
│   └── math_utils.cpp
└── main/                 # 🚀 入口程序目录
    ├── CMakeLists.txt    # 🛠️ main 子目录配置文件
    └── main.cpp
```

---

## 🛠️ 2. 各层级 CMakeLists.txt 配置详解

各个层级的 `CMakeLists.txt` 职责分明，命令搭配如下。

### 🏠 1. 根目录 CMakeLists.txt

**职责**：项目全局配置，定义项目信息，组织子目录。

```cmake
# 1. 指定最低 CMake 版本要求
cmake_minimum_required(VERSION 3.10)

# 2. 定义项目名称和版本号
project(MyProject VERSION 1.0)

# 3. 按依赖顺序引入子目录（先编译库，再编译主程序）
add_subdirectory(src)
add_subdirectory(main)
```

### 📦 2. 库代码子目录 src/CMakeLists.txt

**职责**：生成库文件，并透传自己用到的头文件路径。

```cmake
# 1. 将源文件编译为静态库（STATIC）或动态库（SHARED），目标命名为 math_lib
add_library(math_lib STATIC math_utils.cpp)

# 2. 指定头文件路径，并使用 PUBLIC 作用域
#    PUBLIC 表示：math_lib 本身编译需要此头文件，且“任何链接 math_lib 的其他目标”也会自动获得此头文件路径
target_include_directories(math_lib PUBLIC ${CMAKE_SOURCE_DIR}/include)
```

### 🚀 3. 入口程序子目录 main/CMakeLists.txt

**职责**：生成可执行文件，并链接所依赖的库。

```cmake
# 1. 将 main.cpp 编译为可执行文件 main_prog
add_executable(main_prog main.cpp)

# 2. 链接 src 目录中生成的 math_lib 库
#    由于 math_lib 使用了 PUBLIC 声明头文件路径，main_prog 会自动继承，无需额外配置 include
target_link_libraries(main_prog PRIVATE math_lib)
```

## 🔑 3. 核心命令速查表

| 命令 | 作用 | 常见位置 |
| --- | --- | --- |
| `cmake_minimum_required()` | 声明支持的最低 CMake 版本 | 根目录 |
| `project()` | 定义项目名称和基本属性 | 根目录 |
| `add_subdirectory()` | 添加子目录并执行该目录下的 `CMakeLists.txt` | 根目录 |
| `add_library()` | 将源文件打包为库（`STATIC` / `SHARED`） | 库子目录 |
| `target_include_directories()` | 为指定目标配置头文件搜索路径 | 库子目录 |
| `add_executable()` | 将源文件编译为可执行文件 | 程序入口子目录 |
| `target_link_libraries()` | 为目标建立库链接依赖关系 | 程序入口子目录 |

---

## 💡 4. 关键字补充：PUBLIC vs PRIVATE vs INTERFACE

在配置头文件路径或库依赖时，作用域关键字的作用如下：

- **`PRIVATE`**：仅当前目标内部使用，不传递给依赖项。
- **`PUBLIC`**：当前目标内部使用，且自动传递给依赖项（最常用）。
- **`INTERFACE`**：当前目标内部不使用（如仅有 `.h` 的纯头文件库 Header-only），仅传递给依赖项。
