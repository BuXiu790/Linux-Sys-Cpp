# 📝 单元测试（Unit Testing）核心知识点笔记

## 一、单元测试基本概念 🎯

- **定义**：对软件中的最小可测试单元（通常是函数或类）进行检查和验证。
- **核心目的**：保证代码质量、防止回归错误、提升重构信心、降低调试成本。

---

## 二、结构规范：AAA 模式 📐

一个良好的测试用例通常分为三个明确的步骤：

- **Arrange（准备）**：设置测试环境、准备输入参数与对象。
- **Act（执行）**：调用被测试的函数或方法，获取结果。
- **Assert（断言）**：检查实际结果是否符合预期的输出或状态。

---

## 三、良好单元测试的 FIRST 原则 ⚡

- **F - Fast（快速）**：测试应当在毫秒级内完成，方便频繁运行。
- **I - Isolated（隔离）**：测试用例之间不能相互依赖，运行顺序不影响结果。
- **R - Repeatable（可重复）**：在任何环境（本地、CI/CD 自动化构建）下运行结果均一致。
- **S - Self-validating（自验证）**：测试结果只有成功或失败，无需人工判断。
- **T - Timely（及时）**：单元测试应紧跟代码编写，甚至先于代码（TDD）。

---

## 四、隔离外部依赖：测试双身（Test Doubles）🎭

为了摆脱真实数据库、网络、文件系统等外部依赖，我们需要使用测试双身替换真实对象：

| 类型 | 核心作用 | 适用场景 |
| --- | --- | --- |
| **Dummy（虚设对象）** 🪆 | 仅仅填补参数列表，测试中完全不被调用 | 满足构造函数参数要求 |
| **Stub（存根）** 📥 | 提供固定预设的返回值（关注数据输入） | 模拟数据库查询、API 数据返回 |
| **Mock（模拟对象）** 🔍 | 验证行为（记录调用次数、参数是否正确） | 验证发送邮件、日志记录、扣款操作 |
| **Fake（伪对象）** ⚙️ | 包含简化的真实业务逻辑（但不适合生产） | 内存数据库（用 `std::unordered_map` 代替真实数据库） |
| **Spy（间谍）** 🕵️ | 包装真实对象，保留真实逻辑的同时记录调用状态 | 监控真实对象的调用频次 |

---

## 五、C++ 中的依赖解耦技术 🛠️

要在 C++ 中成功注入测试双身，必须解除代码间的紧密耦合。

### 运行期多态（基于接口/虚函数）

- 定义抽象基类（Pure Virtual Interface）。
- 被测类通过指针或引用（`std::shared_ptr` / 引用）持有接口。
- **优点**：结构清晰。
- **缺点**：存在虚函数表调用的微小开销。

### 编译期多态（基于模板 / Concepts）

- 使用 C++ 模板（Template）将依赖作为类型参数传入。
- **优点**：零运行时开销（Zero-overhead），性能极高。
- **缺点**：编译时间增加，报错信息可能较长。
