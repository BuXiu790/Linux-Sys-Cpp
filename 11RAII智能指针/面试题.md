1. 什么是 RAII？

标准回答：

RAII 是 Resource Acquisition Is Initialization，即资源获取即初始化。它把资源生命周期绑定到对象生命周期：构造函数中获取资源，析构函数中释放资源。这样对象离开作用域时会自动调用析构函数，从而保证资源释放，尤其能解决异常和多分支返回导致的资源泄漏问题。

2. 为什么 C++ 需要智能指针？

标准回答：

因为手动 new/delete 容易出现内存泄漏、重复释放、悬空指针，尤其在异常、多返回路径、复杂对象所有权场景下难以维护。智能指针利用 RAII 自动释放资源，并通过类型语义表达所有权关系。

3. unique_ptr 的核心语义是什么？

标准回答：

unique_ptr 表示独占所有权。同一时刻只能有一个 unique_ptr 拥有某个资源。它不能拷贝，只能移动。离开作用域时会自动释放资源。

4. 为什么 unique_ptr 不能拷贝？

标准回答：

因为如果拷贝，会有两个 unique_ptr 同时管理同一块资源，析构时会发生双重释放。为了保证所有权唯一，unique_ptr 删除了拷贝构造和拷贝赋值，只允许移动语义转移所有权。

5. unique_ptr 移动之后，原对象还能用吗？

标准回答：

原对象仍然是有效对象，但通常变为空，不再拥有资源。可以重新赋值、reset 或析构，但不能直接解引用。使用前应该判断是否为空。

6. make_unique 相比直接 new 有什么好处？

标准回答：

make_unique 可以避免裸 new 暴露在业务代码里，代码更简洁，并且异常安全性更好。它能在一个表达式中完成对象创建和智能指针接管，减少资源泄漏风险。现代 C++ 中优先使用 make_unique。

7. auto_ptr 为什么被废弃？

标准回答：

auto_ptr 的拷贝会转移所有权，这和普通拷贝语义相矛盾，容易导致原指针意外变空，也不适合放入 STL 容器。unique_ptr 明确禁止拷贝，只允许移动，语义更清晰、更安全，因此替代了 auto_ptr。

8. get、release、reset 有什么区别？

标准回答：

get() 返回内部裸指针，只是观察，不转移所有权；release() 放弃所有权并返回裸指针，但不释放资源；reset() 释放当前资源，并可以接管新资源。最危险的是 release()，因为之后必须手动释放或交给其他对象管理。

9. unique_ptr 可以放进 vector 吗？

标准回答：

可以。unique_ptr 不可拷贝，但可以移动。vector<unique_ptr<T>> 是合法的，插入时需要使用 move 或 make_unique。容器扩容时会移动元素，不会拷贝资源。

示例：

vector<unique_ptr<int>> v;
v.push_back(make_unique<int>(10));
10. 多态场景下使用 unique_ptr 要注意什么？

标准回答：

如果用 unique_ptr<Base> 指向 Derived 对象，基类析构函数必须声明为虚析构函数，否则通过基类指针删除派生对象时，派生类析构函数可能不会被调用，导致资源释放不完整。

11. unique_ptr 和 shared_ptr 的区别？

标准回答：

unique_ptr 表示独占所有权，不能拷贝，只能移动，开销很低；shared_ptr 表示共享所有权，通过引用计数管理资源，可以拷贝，但有额外开销，并且可能出现循环引用。能用 unique_ptr 就优先用 unique_ptr，只有确实需要共享所有权时才用 shared_ptr。

12. RAII 在后端开发中有什么实际价值？

标准回答：

后端系统中有大量资源需要可靠释放，比如 socket、文件描述符、数据库连接、互斥锁、线程对象等。RAII 可以把这些资源封装进对象，利用析构函数自动释放，避免内存泄漏、句柄泄漏和死锁，是 C++ 后端工程稳定性的基础。
