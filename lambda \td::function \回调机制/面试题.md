1. lambda 的本质是什么？

lambda 本质是编译器生成的匿名函数对象，也叫闭包对象。

它会把捕获的变量保存成对象的数据成员，把 lambda 函数体变成 operator()。

例如：

auto f = [x](int y) { return x + y; };

大概等价于一个带有 int x 成员变量，并重载了 operator()(int) 的类。

2. lambda 捕获列表有什么作用？

捕获列表决定 lambda 能不能访问外部局部变量，以及以什么方式访问。

常见方式：

[x]   // 值捕获
[&x]  // 引用捕获
[=]   // 默认值捕获
[&]   // 默认引用捕获

值捕获保存副本，引用捕获保存引用。

值捕获更安全，引用捕获要注意生命周期。

3. 值捕获和引用捕获的区别是什么？

值捕获是在 lambda 创建时复制一份变量，之后外部变量变化不会影响内部副本。

引用捕获保存的是外部变量的引用，外部变量变化会影响 lambda 内部看到的值。

但是引用捕获有生命周期风险，如果外部变量销毁，lambda 里引用就悬空。

4. lambda 为什么默认不能修改值捕获变量？

因为 lambda 的 operator() 默认是 const 的。

值捕获的变量作为闭包对象的数据成员，在默认 const operator() 中不能被修改。

如果需要修改副本，需要加 mutable：

auto f = [x]() mutable {
    x++;
};
5. std::function 是什么？

std::function 是 C++ 标准库提供的通用可调用对象包装器。

它可以保存普通函数、lambda、函数对象等，只要参数和返回值匹配。

例如：

std::function<void(int)> f;

表示 f 可以保存任何参数为 int、返回值为 void 的可调用对象。

6. std::function 的底层原理是什么？

核心思想是类型擦除。

不同 lambda 的真实类型不同，但 std::function<void()> 可以把它们包装成统一类型。

这样用户不需要关心底层具体 callable 的类型，只需要关心调用形式。

代价是可能有间接调用、类型擦除和堆分配开销。

7. std::function 为空时调用会发生什么？

如果 std::function 没有绑定任何可调用对象，直接调用会抛出：

std::bad_function_call

所以调用前应该判断：

if (f) {
    f();
}
8. lambda 和普通函数指针有什么区别？

普通函数指针只能指向普通函数，不能保存带捕获的 lambda。

不带捕获的 lambda 可以转换为函数指针。

带捕获的 lambda 本质上有状态，需要保存捕获变量，所以不能直接转换成普通函数指针。

9. 为什么带捕获的 lambda 不能转成函数指针？

因为函数指针只保存函数地址，不保存额外状态。

带捕获的 lambda 需要保存捕获变量，比如：

int x = 10;
auto f = [x]() { return x; };

这个 lambda 里有状态 x，普通函数指针无法保存这个状态。

10. 什么是回调函数？

回调函数就是把一段函数逻辑提前传给某个模块，等事件发生时由这个模块反过来调用。

例如网络库收到消息后调用用户注册的 onMessage。

回调可以降低模块耦合，让框架负责事件检测，用户负责具体处理逻辑。

11. std::function 和模板参数接收 lambda 有什么区别？

std::function 接口统一，可以作为成员变量保存，也可以放进容器，适合回调系统。

模板参数保留 callable 的真实类型，性能更好，容易内联，但不适合在运行期统一存储不同类型的 callable。

简单说：

std::function

适合统一接口和保存回调。

template <typename F>

适合高性能泛型调用。

12. 异步回调中捕获 this 有什么风险？

如果对象已经析构，而异步回调还在事件循环、线程池或网络库中等待执行，那么 lambda 捕获的 this 就会变成悬空指针。

调用时访问成员变量会产生未定义行为。

实际项目中应该谨慎捕获 this，必要时使用 shared_ptr / weak_ptr 管理生命周期
